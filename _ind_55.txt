**Constat architectural :** le suivi des indicateurs n'est **pas un module isolé**. Il repose sur **trois piliers** :

```text
RBM/GAR (indicateurs + mesures IOV)
        +
Suivi Physique (collectes par campagne / activité)
        +
Plan Stratégique (indicateurs_strategiques)
        ↓
Reporting (rbm_gar, cockpit, feux dashboard)
```

Le seeder `SuiviIndicateursSeeder` **n'existe pas** dans le dépôt.

### Collecte et mesure (IOV)

- Saisie manuelle des **mesures** par période (`MesureController` + `MesureService`)
- Champs : période, valeur réalisée, commentaire, responsable (`saisi_par`), statut
- Calcul automatique : **taux d'atteinte** et **feu** (vert/orange/rouge) selon cible et seuil

```15:27:app/Services/Rbm/MesureService.php
    public function calculerTauxEtFeu(Indicateur $indicateur, float $valeurRealisee): array
    {
        $cible = (float) ($indicateur->valeur_cible ?? 0);
        $taux = $cible > 0 ? round(($valeurRealisee / $cible) * 100, 2) : ($valeurRealisee > 0 ? 100.0 : 0.0);

        $seuil = (float) ($indicateur->seuil_alerte ?? 50);
        $feu = match (true) {
            $taux >= 75 => 'vert',
            $taux >= $seuil => 'orange',
            default => 'rouge',
        };

        return ['taux_atteinte' => $taux, 'feu' => $feu];
    }
```

## 5. Incohérences détectées

### 5.1 Double modèle de collecte non unifié

| Modèle | Granularité | Usage |
|--------|-------------|-------|
| `mesures` | Indicateur IOV / période | RBM/GAR |
| `collectes` | Activité / campagne | Suivi physique trimestriel |

Les deux coexistent sans couche de **réconciliation** explicite dans un hub unique.

### 5.2 Écrasement des mesures sans historisation

`MesureService::enregistrer()` utilise `updateOrCreate(['periode' => …])` : une resaisie sur la même période **remplace** la valeur sans conserver l'ancienne version.

### 5.3 Mesures non auditées

Le modèle `Mesure` **n'utilise pas** le trait `Auditable` (contrairement à `Collecte`). Une mesure validée ne peut plus être modifiée (policy), mais les étapes intermédiaires ne sont pas journalisées dans `journaux_audit`.

### 5.4 Évolution cockpit ≠ évolution indicateurs

Le cockpit reporting trace l'**évolution des paiements** mensuels, pas l'évolution des indicateurs :

```356:363:app/Services/Reporting/ReportingService.php
        // Évolution mensuelle des décaissements (paiements validés)...
        $evolution = collect(range(1, 12))->map(fn ($m) => [
            'mois' => $m,
            'montant' => (float) $paiements->filter(...)->sum('montant'),
        ]);
```

### 5.5 Permissions : convention divergente

| Attendu | Réel |
|---------|------|
| `indicateurs.view` | `indicateur.voir` |
| `indicateurs.collect` | `indicateur.creer` + `suivi.creer` |
| `indicateurs.validate` | `indicateur.valider` + `suivi.valider` |
| `indicateurs.admin` | `rbm.admin` (partiel) |

### 5.6 Indicateurs stratégiques vs RBM

Deux registres parallèles (`indicateurs` et `indicateurs_strategiques`) sans consolidation automatique dans un répertoire unique.

## 6. Risques qualité des données

| Risque | Gravité | Description |
|--------|---------|-------------|
| **Perte d'historique mesures** | Élevée | Resaisie même période = écrasement |
| **Double saisie IOV / collecte** | Moyenne | Risque d'incohérence phys./fin. vs mesures IOV |
| **Collecte sans justificatif** | Moyenne | Configurable ; contournable si désactivé |
| **Feux calculés sur cible nulle** | Faible | Taux = 100 % si réalisé > 0 sans cible |
| **Pas de validation statistique** | Moyenne | Outliers non détectés automatiquement |

| Risque | Gravité | Description |
|--------|---------|-------------|
